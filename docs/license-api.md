# מפרט API — רישיונות ועדכונים

החוזה בין התוסף "משפר חנויות ווקומרס" לבין `app.multidigital.co.il`.

**המפרט אושר על ידי צוות השרת** (אוגוסט 2026), והמסמך הזה משקף את המימוש בפועל.
הצד השני של החוזה הוא חנויות לקוחות שאי אפשר לפרוס אליהן קוד בקלות — לכן
**הוספת שדות בטוחה, שינוי צורה של שדה קיים אינו.**

**כתובת בסיס:** `https://app.multidigital.co.il/api/license/v1`

ניתן לשנות אותה בצד הלקוח בלי לגעת בקוד:

```php
define( 'WC_STORE_ENHANCER_LICENSE_API', 'https://staging.multidigital.co.il/api/license/v1' );
```

## דרישות חוצות־נקודות־קצה

| דרישה | פירוט |
|---|---|
| **HTTPS בלבד** | התוסף מסרב לפעול מול HTTP. התשובה שלכם קובעת איזו חבילת PHP מותקנת אצל הלקוח — ה-TLS הוא ערובת השלמות היחידה. |
| **שיטה** | `POST`, גוף `application/x-www-form-urlencoded` (זה מה ש-`wp_remote_post` שולח כברירת מחדל). |
| **תשובה** | JSON תמיד, גם בשגיאה. תשובה שאינה JSON נחשבת אצל הלקוח לתקלת תקשורת. |
| **קודי סטטוס** | `200` לכל תשובה עסקית, כולל "רישיון לא תקף". `4xx` שמור לשגיאות בקשה ולנקודת `update`. |
| **ללא אימות נוסף** | המפתח הוא האישור. אין טוקנים, אין כותרות מיוחדות. |
| **הגבלת קצב** | 30 בקשות לדקה לכל IP. חריגה מחזירה `429`, שנחשב תקלת תקשורת. |

### פרמטרים שנשלחים בכל בקשה

| שדה | סוג | תיאור |
|---|---|---|
| `key` | string | המפתח כפי שהלקוח הדביק — בלי ניקוי בצד התוסף. |
| `site` | string | `home_url()` כמו שהוא. |
| `version` | string | גרסת התוסף המותקנת. נשלח גם בבדיקה היומית. |

**הנרמול נעשה בשרת, לא בתוסף.** רווחים בקצוות, אותיות קטנות ומפתח בלי מקפים —
כולם מתקבלים. כתובת האתר מנורמלת אצל השרת (סכימה, `www.`, לוכסן בסוף, ורגישות
לרישיות), כך ש-`http://shop.co.il`, `https://www.shop.co.il/` ו-`https://shop.co.il`
הם אותו אתר. מעבר ל-HTTPS או שחזור גיבוי לא יבזבזו מקום במכסה.

## מבנה התשובה המשותף

`activate`, `deactivate` ו-`check` מחזירות את אותו אובייקט:

```json
{
  "status": "valid",
  "expires": "2027-08-16",
  "sites_limit": 3,
  "sites_used": 1,
  "message": ""
}
```

| שדה | חובה | הערות |
|---|---|---|
| `status` | ✔ | אחד מהערכים בטבלה למטה. כל ערך אחר יטופל כ-`invalid`. |
| `expires` | | `YYYY-MM-DD`. מחרוזת ריקה = ללא תפוגה. |
| `sites_limit` | | 0 = ללא הגבלה. |
| `sites_used` | | כמה אתרים רשומים כרגע. |
| `message` | | טקסט **בעברית שמוצג ללקוח כמו שהוא**. השאירו ריק כשהכל תקין. |

### ערכי `status`

| ערך | מתי | מה הלקוח יראה |
|---|---|---|
| `valid` | מפתח פעיל, בתוקף, והאתר רשום עליו | "פעיל" — ועדכונים זורמים |
| `expired` | התוקף עבר | "פג תוקף" |
| `limit` | ניסיון להפעיל על אתר נוסף מעבר למכסה | "חריגה ממספר האתרים" |
| `invalid` | מפתח לא מוכר, מבוטל, או שהאתר לא רשום עליו | "מפתח לא מוכר" |

> **הכלל שקובע את כל השאר:** `status` שאינו `valid` הוא תשובה עסקית תקינה —
> חוזר עם `200`.
>
> `5xx`, `429` או ניתוק הם **תקלת תקשורת**, והתוסף **שומר על המצב הקודם** במקום
> לבטל את הרישיון. בלי זה, דקת תחזוקה אחת בשרת הייתה מבטלת רישיונות בכל החנויות
> בבת אחת.

## נקודות הקצה

### `POST /activate`

קושר מפתח לאתר. נקראת פעם אחת, כשהלקוח לוחץ "הפעלת רישיון".

**לוגיקה נדרשת:**
1. מפתח לא מוכר או מבוטל → `invalid`.
2. תוקף עבר → `expired`.
3. האתר **כבר רשום** על הרישיון → `valid`. הפעלה חוזרת אינה תופסת מקום נוסף. (זה קורה בפועל: העברת אתר בין שרתים, שחזור גיבוי.)
4. האתר חדש והמכסה מלאה → `limit`.
5. אחרת → רשמו את האתר והחזירו `valid`.

### `POST /deactivate`

משחררת את האתר מהרישיון, כדי שהלקוח יוכל להעביר אותו לאתר אחר.

מחזירה `{"status":"inactive","message":""}`. **תמיד `200`**, גם למפתח לא מוכר —
הלקוח מוחק את המפתח מקומית בכל מקרה, ואין סיבה להכשיל אותו.

### `POST /check`

בדיקה תקופתית. הלקוח קורא לה **פעם ביום ב-cron**, לא בטעינת עמוד.

זהה ל-`activate` אבל **בלי לרשום אתר חדש**: אם האתר לא רשום על הרישיון,
החזירו `invalid` עם הודעה מתאימה. כדאי לעדכן `last_seen` ו-`version` לאתר הרשום
— ככה תדעו מי חי ומי לא.

### `POST /update`

מחזירה את פרטי הגרסה להפצה. נקראת עד פעם ב-6 שעות (לקוח מחזיק קאש).

זו נקודת הקצה היחידה שמחזירה קוד שגיאה: **`403`** כשהרישיון אינו מכסה את האתר,
עם `{"status":"...","message":"..."}`. התוסף יבין שאין עדכון ולא יציג כלום.

**מקרה שכדאי להכיר:** כשעדיין לא הוגדרה גרסה מופצת, השרת מחזיר `200` עם
`{"status":"valid"}` **בלי** שדה `version`. זה "אין עדכון", לא כשל רישיון —
והתוסף מטפל בו ככה ולא מציג שגיאה.

תשובה מוצלחת:

```json
{
  "version": "1.23.0",
  "download_url": "https://app.multidigital.co.il/api/license/v1/download?...",
  "homepage": "https://multidigital.co.il/wc-store-enhancer",
  "requires": "6.4",
  "requires_php": "8.0",
  "tested": "9.9",
  "changelog": "<ul><li>תיקון בחירת וריאציה</li></ul>",
  "last_updated": "2026-08-16 10:00:00"
}
```

| שדה | חובה | הערות |
|---|---|---|
| `version` | ✔ | מספר גרסה נקי. `v` מוביל יוסר אוטומטית. |
| `download_url` | ✔ | **חייב HTTPS.** ראו סעיף ההורדה. |
| `changelog` | | HTML בסיסי. מוצג בחלון "הצג פרטים" של וורדפרס. |
| `requires` / `requires_php` / `tested` | | ברירות מחדל: `6.4` / `8.0` / `9.9`. |

### `GET {download_url}`

מגישה את ה-ZIP. וורדפרס פונה אליה **ישירות**, בלי כותרות מהתוסף — לכן כל מה
שנדרש לאימות חייב להיות בתוך הכתובת עצמה.

מותר להחזיר `302` לקובץ הסופי; וורדפרס עוקב אחרי הפניות.

**הכתובת חייבת לעמוד בשלושה תנאים:**

1. **המפתח לא מופיע בה.** קישורי הורדה מגיעים ללוגים של פרוקסי, לפניות תמיכה ולצילומי מסך. השתמשו בגיבוב של המפתח, לא במפתח.
2. **חתומה ומוגבלת בזמן.** HMAC על (גיבוב־מפתח + כתובת אתר + זמן תפוגה), עם מפתח סוד שרק אצלכם. תוקף של שעה מספיק בהחלט.
3. **קשורה לאתר אחד.** קישור שנתפס לא יעבוד מאתר אחר.

מימוש לדוגמה:

```
sig = hmac_sha256( key_hash + "|" + site + "|" + expires, SERVER_SECRET )
url = /download?k={key_hash}&site={site}&exp={expires}&sig={sig}
```

בצד ההורדה: ודאו ש-`exp` בעתיד, חשבו מחדש את `sig` והשוו ב-**השוואה בזמן קבוע**
(`hash_equals` / `crypto.timingSafeEqual`), ואז ודאו שהאתר עדיין רשום על הרישיון.

הקישור נבדק **שוב** בזמן ההורדה: רישיון שבוטל אחרי שהקישור נוצר ייחסם, גם בתוך
שעת התוקף.

## אחסון המפתחות

- **אל תשמרו מפתחות כטקסט גלוי.** שמרו `hmac_sha256(key, SERVER_SECRET)` וחפשו לפיו. דליפה של טבלת מסד לא תיתן לאף אחד מפתח עובד.
- **השוו בזמן קבוע.** השוואת מחרוזות רגילה מדליפה מידע דרך זמן התגובה.
- **מפתח קריא לאדם.** פורמט `XXXX-XXXX-XXXX-XXXX` מהאלפבית `A-Z` ו-`2-9`, **בלי** התווים `O 0 I 1` שמתבלבלים בהכתבה טלפונית ובצילום מסך.
- **התוסף אינו דוחה מפתח על סמך פורמט** — הוא שולח כמו שהוא ונותן לתשובה להכריע, כך ששינוי פורמט בעתיד לא מחייב עדכון בכל החנויות.
- מכיוון שהמפתח אינו נשמר כטקסט, **אי אפשר לשלוח ללקוח את המפתח שלו שוב**. מפתח שאבד מונפק מחדש והישן מפסיק לעבוד מיד. כדאי שההודעה ב-`invalid` תרמוז ללקוח לבדוק את המייל שקיבל.

## מה כדאי שיהיה במסך הניהול שלכם

מעבר ל-API, מה שיחסוך לכם זמן בפועל:

- הנפקת מפתח: לקוח, אימייל, מספר אתרים, תאריך תפוגה (ריק = ללא הגבלה).
- רשימת רישיונות עם **האתרים שרשומים על כל אחד** ומתי נראו לאחרונה.
- ביטול/הפעלה מחדש, ושינוי מכסה ותוקף במקום.
- ניתוק אתר בודד מרישיון — יבוא מפניות תמיכה ("החלפתי דומיין").
- **גרסה מופצת אחת**: מספר גרסה, כתובת ZIP, changelog. זה מה שנקודת `update` מחזירה.

## חיבור למכירה

כשעסקה נסגרת: הנפיקו מפתח, שלחו אותו במייל, וקבעו תפוגה לפי סוג המנוי. חידוש =
דחיית `expires_at`. **אין צורך בכלום נוסף בצד התוסף** — הוא בודק פעם ביום
וימשיך לקבל עדכונים ברגע שהתאריך זז.

## איך לבדוק שזה עובד

1. הנפיקו מפתח ידנית והדביקו אותו באתר בדיקה תחת **הגדרות ← רישיון**. אמור להופיע "פעיל".
2. הגדירו במערכת גרסה **גבוהה** מהמותקנת. בעמוד התוספים בוורדפרס אמור להופיע עדכון תוך 6 שעות, או מיד אחרי "בדוק עדכונים עכשיו".
3. לחצו "עדכן" — ההתקנה אמורה להצליח.
4. הגדירו תפוגה בעבר. בבדיקה הבאה המצב יהפוך ל"פג תוקף", העדכונים ייעצרו, **והתוסף ימשיך לעבוד רגיל**.
5. הפעילו על אתר נוסף מעבר למכסה → `limit`, והתוסף יציג את ההודעה שחזרה.
