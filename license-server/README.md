# שרת הרישיונות

תוסף וורדפרס נפרד שמותקן **רק על multidigital.co.il** — לא על אתרי לקוחות.
הוא מנפיק מפתחות רישיון, קושר אותם לאתרים, ומגיש את העדכונים לתוסף.

## התקנה

1. דחסו את התיקייה `license-server` ל-ZIP והעלו אותה כתוסף ל-multidigital.co.il.
2. הפעילו. יופיע תפריט חדש בשם **רישיונות**.

## פרסום גרסה חדשה

1. בנו את ה-ZIP של התוסף כרגיל.
2. העלו אותו לשרת (מדיה או תיקייה) והעתיקו את הכתובת.
3. **רישיונות ← הגרסה המופצת**: מלאו מספר גרסה, כתובת ה-ZIP ו"מה חדש". שמרו.

אתרים עם רישיון פעיל יראו את העדכון בעמוד התוספים תוך כמה שעות (הלקוח בתוסף
מחזיק קאש של 6 שעות; "בדוק עדכונים עכשיו" מדלג עליו).

## הנפקת רישיון ללקוח

**רישיונות ← הנפקת רישיון**: שם, אימייל, מספר אתרים ותאריך תפוגה (ריק = ללא
הגבלה). המפתח שנוצר מוצג פעם אחת בראש העמוד ותמיד בטבלה — זה מה שמוסרים ללקוח.

הלקוח מדביק אותו בתוסף שלו תחת **הגדרות ← רישיון**.

## מה קורה כשרישיון פג או מבוטל

**רק העדכונים נעצרים.** התוסף וכל המודולים ממשיכים לעבוד בדיוק כמו קודם באתר
הלקוח, ומופיעה הודעה שקטה בניהול. זו החלטה מכוונת: כיבוי פיצ׳רים בחנות פעילה
בגלל חשבונית שאיחרה גורם נזק גדול בהרבה מגובה החוב.

## נקודות אבטחה

- **המפתח לא נשמר בצורה שאפשר לגנוב ממנה.** ההשוואה נעשית מול `hash_hmac` עם
  ה-salt של האתר, ובעזרת `hash_equals` כדי שלא ידלוף מידע דרך זמן התגובה.
- **קישור ההורדה לא מכיל את המפתח** — רק את הגיבוב שלו, את כתובת האתר ואת זמן
  התפוגה, חתומים יחד. קישור שנתפס בלוג של פרוקסי או בפניית תמיכה לא ניתן להמרה
  חזרה למפתח, לא עובד מאתר אחר, ופג תוך שעה.
- **התקשורת חייבת להיות HTTPS.** התשובה של השרת קובעת איזו חבילת PHP מותקנת אצל
  הלקוח, ולכן ה-TLS הוא ערובת השלמות. הלקוח מסרב לפעול מול כתובת שאינה HTTPS.
- **תקלת תקשורת אינה פסק דין.** אם השרת לא זמין, הלקוח שומר על המצב האחרון
  שידוע לו ולא מאבד את הרישיון בגלל דקה רעה אצל המארח.

## שינוי כתובת השרת (לבדיקות)

בתוסף הלקוח, ב-`wp-config.php`:

```php
define( 'WC_STORE_ENHANCER_LICENSE_SERVER', 'https://staging.multidigital.co.il' );
```

## נקודות הקצה

כולן תחת `/wp-json/wcse-license/v1/`:

| נתיב | תפקיד |
|---|---|
| `activate` | קושר מפתח לאתר, מחזיר מצב |
| `deactivate` | משחרר את האתר מהרישיון |
| `check` | בדיקה תקופתית (הלקוח קורא פעם ביום ב-cron) |
| `update` | מחזיר את פרטי הגרסה וקישור הורדה חתום |
| `download` | מאמת את החתימה ומפנה לקובץ |
